## 1 任务目标  

在本课时中，我们将围绕“**领域预训练（Pre-Training, PT）**”这一核心主题，构建一个从数据准备到模型评测的完整实践流程。具体而言，我们将选用 DuReader（千言）数据集中的篇章文本，在已有的基座模型上进行继续预训练，使模型能够更好地学习并适应特定领域的文本分布特征。

在实际应用中，通用大模型虽然具备较强的语言理解与生成能力，但在面对特定领域（如阅读理解场景、知识问答场景）时，往往存在表达不准确、上下文建模不足等问题。因此，通过引入领域相关语料进行预训练，可以有效提升模型对该类文本的建模能力，从而改善生成质量与预测准确性。

在完成模型训练后，我们还将构建一套**可量化的评测机制**，通过“prefix → continuation”的续写任务，对比基座模型与预训练模型在以下三个指标上的表现：

- **PPL（Perplexity，困惑度）**：衡量模型对文本的整体预测能力  
- **交叉熵 Loss**：反映模型对真实分布的拟合程度  
- **BLEU（n-gram 重叠指标）**：评估生成文本与参考文本的相似度  

通过这一过程，你将不仅掌握如何进行领域预训练，还能够理解**如何设计合理的评测方式来验证模型效果提升**，从而形成一个完整的“训练—评测—对比分析”的实践闭环。

## 2 数据集简介  

### 2.1 来源背景  

本实验选用的数据集为：

- **名称**：[DuReader（千言·阅读理解）](https://huggingface.co/datasets/luozhouyang/dureader)，HuggingFace 标识为 `luozhouyang/dureader`。  

DuReader 数据集最初由百度发布，是一个面向真实搜索场景的中文机器阅读理解数据集，后续被纳入“千言”数据体系中，用于评测模型在复杂语境下的理解与推理能力。该数据集包含了大量来自真实用户查询的问题，以及与之对应的篇章内容和答案标注，具有较强的实际应用背景。

与一般的纯文本语料相比，DuReader 的特点在于：

- 文本来源真实，语言表达自然  
- 篇章内容较长，包含丰富上下文信息  
- 涉及多种主题，具有一定的领域多样性  

在本实验中，我们并不直接使用问答对，而是重点关注其中的**篇章正文（context）**，将其作为语言模型的训练语料。这种处理方式能够更贴近语言模型预训练的本质任务——即通过大量连续文本学习语言分布规律。

此外，我们选择使用该数据集中的：

- **robust（鲁棒性）子集**的 train split  

该子集在构建时更加关注模型在复杂、扰动环境下的表现，因此其文本内容更具挑战性，有助于提升模型的泛化能力。

在具体处理过程中，我们会对每条样本提取其篇章字段（如 `context`），并进行去重操作，最终得到一个**唯一的文本集合（all_contexts）**，作为后续训练与评测的基础数据来源。

### 2.2 数据规模

在实际开展预训练实验时，一个核心问题是：**数据规模如何设定，才能兼顾实验效果与训练成本？**

如果数据规模过小，模型难以学习稳定的语言分布；而数据规模过大，则会显著增加训练时间，不利于教学实验的快速迭代。因此，在本课时中，我们采用一种“**小规模但结构完整**”的数据构建策略，在保证实验可复现性的同时，使读者能够清晰理解完整流程。

整体数据划分如下：

| 项目 | 数值 |
|------|------|
| 训练用篇章 | 约 3,000 条 |
| 评测用样本 | 约 200 条（由篇章切分得到） |

需要注意的是：这些数据**并不是直接来自原始数据集，而是经过处理后生成的结构化数据**。在正式生成之前，我们先来看原始数据长什么样。

因此，第一步是进行字段抽取，只保留篇章正文：

```python
def _get_context(item):
    for key in ('context', 'passage', 'content'):
        val = item.get(key)
        if val and isinstance(val, str) and val.strip():
            return val.strip()
    doc = item.get('doc')
    if isinstance(doc, list) and doc:
        parts = [str(p).strip() for p in doc if p]
        if parts:
            return '\n'.join(parts)
    if isinstance(doc, str) and doc.strip():
        return doc.strip()
    if isinstance(item.get('positive'), str) and item['positive'].strip():
        return item['positive'].strip()
    return ''
```

随后，我们对所有文本进行去重，得到一个“唯一文本集合”：

```python
seen = set()

```

接下来，我们需要构造评测数据。这里不再直接使用整段文本，而是将其转化为一个更贴近模型使用方式的任务：

> 给定前文（prefix），预测后文（continuation）

关键问题在于：如何切分？

我们采用“句子边界切分”方法：

```python
def _split_at_sentence_boundary(text, target_ratio=0.5):
    n = len(text)
    if not n or target_ratio <= 0 or target_ratio >= 1:
        return text[:n // 2], text[n // 2:]
    target_pos = int(n * target_ratio)
    pattern = re.compile(f'[{re.escape(SENTENCE_END_CHARS)}]')
    matches = list(pattern.finditer(text))
    if not matches:
        return text[:target_pos], text[target_pos:]
    best_pos = 0
    best_dist = abs(0 - target_pos)
    for m in matches:
        end = m.end()
        if end >= n:
            continue
        dist = abs(end - target_pos)
        if dist < best_dist:
            best_dist = dist
            best_pos = end
    prefix, continuation = text[:best_pos].strip(), text[best_pos:].strip()
    if not prefix or not continuation:
        return text[:target_pos], text[target_pos:]
    return prefix, continuation
```

将该函数应用到文本后，就可以构造评测样本：

```python
eval_samples = []
for ctx in eval_contexts:
    prefix, continuation = _split_at_sentence_boundary(
        ctx, target_ratio=PREFIX_RATIO)
    if not prefix or not continuation:
        prefix = ctx[:len(ctx) // 2]
        continuation = ctx[len(ctx) // 2:]
    eval_samples.append({'prefix': prefix, 'continuation': continuation})
```

## 3 模型训练

在完成数据准备之后，下一步便进入本课时的核心环节——**基于领域语料的继续预训练（Pre-Training, PT）**。这一阶段的目标，是在通用大模型的基础上，引入 DuReader 篇章数据，使模型进一步适应中文阅读理解场景下的文本分布，从而提升其对长文本语义结构与上下文衔接的建模能力。

本实验选用的基座模型为 **Qwen2.5-0.5B-Instruct**。该模型在通用语料上已经具备较强的语言建模能力，但其对特定领域（如阅读理解篇章）的表达模式仍存在一定偏差。因此，通过在目标领域数据上进行继续预训练，可以有效缩小这种分布差异，使模型在后续任务（如续写、问答等）中表现更加稳定。

在实现层面，本实验依托 LazyLLM 对 LLaMA-Factory 的封装接口，完成从数据加载、训练配置到模型更新的全流程调用。整体流程可以理解为：**加载基座模型 → 指定训练数据 → 配置训练策略 → 执行参数更新**。

具体实现如下：

```python
model = lazyllm.TrainableModule(BASE_MODEL_PATH, target_path=target_path)

model.mode('finetune')\
    .trainset(TRAIN_JSON_PATH)\
    .finetune_method((finetune.llamafactory, {
        'stage': 'pt',
        'finetuning_type': 'full',
        'learning_rate': 3e-5,
        'cutoff_len': 512,
        'val_size': 0.05,
        'optim': 'adamw_torch_fused',
        'bf16': True,
        'fp16': False,
        'per_device_train_batch_size': 8,
        'gradient_accumulation_steps': 4,
        'num_train_epochs': 20,
        'lr_scheduler_type': 'cosine',
        'warmup_ratio': 0.1,
        'save_steps': 20,
        'logging_steps': 5,
        'resume_from_checkpoint': None,
        'save_strategy': 'steps',
        'save_total_limit': 5,
        'launcher': launchers.empty(ngpus=1),
    }))\
    .update()
```

从上述代码可以看出，训练过程被高度模块化封装，但其核心逻辑依然清晰可控：

首先，通过 `TrainableModule` 加载基座模型，并指定训练输出路径 `target_path`。这一目录将在训练过程中自动生成，用于保存不同阶段的 checkpoint 以及最终的合并模型。

随后，调用 `.mode('finetune')` 指定当前任务为微调/预训练模式，并通过 `.trainset(...)` 传入训练数据。需要注意的是，这里的训练数据实际上是在前一阶段动态构建得到的文本集合，其本质是“仅包含篇章正文的语言模型训练语料”。

在训练策略配置中，`stage='pt'` 明确指定当前阶段为**预训练（而非指令微调）**，模型将以语言建模（Language Modeling）的目标进行优化；`finetuning_type='full'` 表示采用**全参数更新**，即模型的所有参数均参与训练，这对于充分吸收领域知识是必要的。

在具体的优化细节上，本实验采用较为稳健的配置组合：学习率设为 `3e-5`，并结合 `cosine` 学习率调度策略与 `warmup_ratio=0.1`，以保证训练初期的稳定性与后期的平滑收敛；同时，通过 `cutoff_len=512` 控制单条样本的最大长度，使训练在显存可控的前提下尽可能覆盖完整上下文信息。

考虑到显存限制与训练效率之间的平衡，采用了 **小 batch + 梯度累积** 的策略（`batch_size=8`，`gradient_accumulation_steps=4`），从而在不增加显存压力的情况下等效扩大批大小，提高梯度估计的稳定性。此外，通过设置 `val_size=0.05` 自动划分验证集，可以在训练过程中对模型性能进行基本监控。

在训练过程管理方面，`save_steps=20` 与 `save_total_limit=5` 控制了 checkpoint 的保存频率与数量上限，既保证了训练过程的可回溯性，又避免了磁盘空间的过度占用。所有 checkpoint 均按照时间戳自动归档，形成清晰的实验记录结构。

整体而言，这一训练流程体现了一个典型的**轻量级领域自适应预训练范式**：在不改变模型结构的前提下，仅通过引入领域语料并进行继续训练，即可显著提升模型在特定任务上的表现。这种方式实现成本低、迁移性强，非常适合作为实际工程中的基础能力增强手段。

在完成本阶段训练后，我们将得到一个“已经适应 DuReader 语料分布”的预训练模型。接下来，即可进入评测环节，通过 PPL、Loss 与 BLEU 等指标，对比分析预训练前后模型性能的变化，从而验证该方法的有效性。

## 4 效果评测

在完成预训练之后，一个关键问题随之而来：**模型到底学到了什么？性能是否真的得到了提升？**  
为回答这一问题，本节将构建一套完整、可复现的评测流程，从“概率建模能力”和“生成质量”两个角度，对基座模型与预训练模型进行系统对比。

与训练阶段类似，评测数据并不是直接“现成给出”的，而是由前一阶段的数据处理流程动态构建得到。其基本形式可以理解为：

> 给定一段文本的前半部分（prefix），让模型预测其后续内容（continuation）

这种设计非常贴近语言模型的实际使用场景，也为后续指标计算提供了清晰的条件约束。

一个典型样本的结构如下（示意）：

```json
{
  "prefix": "……前文内容……",
  "continuation": "……真实后续内容……"
}
```

围绕这一数据形式，我们从两个维度展开评测：

* **建模能力**：模型对“真实后续”的概率预测能力（PPL / Loss）
* **生成能力**：模型自由生成文本与参考答案的接近程度（BLEU）

整个评测流程可以通过如下命令一键执行([完整脚本在此链接](./code/run_dureader.py))：

```bash
python run_dureader.py --mode=eval
```

该脚本会自动完成：数据加载 → 模型推理 → 指标计算 → 结果保存，形成完整评测闭环。

### 4.1 PPL（困惑度）与 Loss

在语言建模任务中，最核心的指标是**交叉熵损失（Loss）**及其指数形式——**困惑度（Perplexity, PPL）**。二者本质上衡量的是：

> 模型对“真实文本”的预测概率是否足够高

在实现上，我们并不是对整段文本计算损失，而是**只关注 continuation 部分**。也就是说：

* prefix 作为已知条件输入模型
* continuation 作为预测目标参与 loss 计算

这一点在代码中体现为对 labels 的“掩码处理”：

```python
labels = input_ids.clone()
labels[:, :prefix_len] = -100  # 屏蔽 prefix 部分
```

通过这种方式，模型只在 continuation 部分计算损失，从而实现“条件语言建模”。

其数学定义如下：

$$\bar{L} = -\frac{1}{N}\sum_{i=1}^{N} \log p_\theta(w_i \mid w_{<i})$$

在此基础上，困惑度定义为：

$$\mathrm{PPL} = \exp(\bar{L})$$

其中各变量含义为：

* $N$：continuation 部分的 token 总数
* $w_i$：第 $i$ 个 token
* $w_{<i}$：其前文上下文（包含 prefix）
* $p_\theta$：模型预测概率

在代码实现中，对每条样本分别计算 loss，再取平均：

```python
with torch.no_grad():
    out = model(input_ids=input_ids, labels=labels)
    loss = out.loss.item()

ppl = torch.exp(torch.tensor(loss)).item()
```

最终得到整个评测集的平均 PPL 和 Loss。

👉 **如何理解这两个指标？**

* Loss 越低 → 模型预测越接近真实分布
* PPL 越低 → 模型“困惑度”越小，即不确定性更低

因此，这两个指标本质上反映的是模型的**语言建模能力**，尤其适合评估预训练效果。

### 4.2 BLEU（生成质量评估）

仅有概率指标还不够，因为模型即使概率分布合理，也可能生成“语义上合理但表达不同”的文本。因此，我们还需要从**生成结果本身**进行评估。

在本实验中，我们采用一种简化版 BLEU 指标（基于 2-gram 的 F1 近似），其核心思想是：

> 比较模型生成文本与参考文本在局部片段上的重合程度

评测流程如下：

1. 输入 prefix
2. 使用模型进行自回归生成
3. 将生成结果与参考 continuation 进行对比

生成过程代码如下：

```python
gen = model.generate(**enc, generation_config=gen_config)

pred_ids = gen[i, prefix_lens[i]:]
pred = tokenizer.decode(pred_ids, skip_special_tokens=True)
```

随后，我们对生成文本与参考文本进行 2-gram 层面的匹配，计算 Precision、Recall 及 F1 分数，从而评估生成文本的局部重合情况。具体公式如下：

$$
\mathrm{Precision} = \frac{|G_{2} \cap R_{2}|}{|G_{2}|}
$$

其中：

- $G_2$：模型生成文本中的所有 2-gram 集合  
- $R_2$：参考文本中的所有 2-gram 集合  
- $|G_2 \cap R_2|$：生成文本与参考文本共享的 2-gram 数量  
- $\mathrm{Precision}$：生成文本中有多少比例的 2-gram 与参考文本匹配  

$$
\mathrm{Recall} = \frac{|G_{2} \cap R_{2}|}{|R_{2}|}
$$

其中：

- $\mathrm{Recall}$：参考文本中有多少比例的 2-gram 被生成文本覆盖  

随后，通过 Precision 与 Recall 计算 F1 分数：

$$
F_1 = \frac{2 \cdot \mathrm{Precision} \cdot \mathrm{Recall}}{\mathrm{Precision} + \mathrm{Recall}}
$$

这里：

- $F_1$ 综合衡量了生成文本与参考文本在 2-gram 层面的匹配程度  
- 数值越高表示生成结果与参考文本越接近  


通过这种方式，我们既考虑了生成文本的覆盖率，也考虑了生成的准确性，使 BLEU 指标能够合理反映模型生成质量。

在代码中，这一过程被封装为：

```python
def _bleu_simple(ref: str, pred: str) -> float:
    def _ngrams(s, n):
        s = ''.join(s.split())
        if len(s) < n:
            return []
        return [s[i:i + n] for i in range(len(s) - n + 1)]
    r, p = ''.join(ref.split()), ''.join(pred.split())
    if not r or not p:
        return 0.0
    bigram_r = set(_ngrams(r, 2))
    bigram_p = _ngrams(p, 2)
    if not bigram_p:
        return 0.0
    hit = sum(1 for b in bigram_p if b in bigram_r)
    prec = hit / len(bigram_p)
    rec = hit / len(bigram_r) if bigram_r else 0.0
    if prec + rec == 0:
        return 0.0
    return 2 * prec * rec / (prec + rec)
```

👉 **如何理解 BLEU？**

* 数值越高 → 生成文本与参考越接近
* 反映的是“表达一致性”，而非概率准确性

需要注意的是，在仅进行预训练（PT）而未进行监督微调（SFT）的情况下：

* BLEU 提升通常**不如 PPL 明显**
* 因为模型更擅长“建模分布”，而非“生成固定答案”

### 4.3 小结：指标体系的互补性

通过上述设计，我们构建了一套**相互补充的评测体系**：

| 指标         | 关注点    | 特点       |
| ---------- | ------ | -------- |
| PPL / Loss | 概率建模能力 | 对语言模型最敏感 |
| BLEU       | 生成文本质量 | 更贴近实际输出  |

可以这样理解：

* **PPL / Loss** 回答：“模型是否学会了这个分布？”
* **BLEU** 回答：“模型生成得像不像参考答案？”

二者结合，能够从“内部建模能力”与“外部生成表现”两个角度，对预训练效果进行全面评估。

至此，我们完成了从数据构建 → 模型训练 → 指标评测的完整闭环。接下来，只需对比基座模型与预训练模型在这些指标上的变化，即可直观验证领域预训练的实际收益。

### 4.3 评测结果

在完成模型的全参数预训练后，我们需要对模型在实际任务场景下的表现进行量化评估。本节将以 DuReader 数据集中的评测子集为例，展示从数据预览、指标计算到结果解读的完整流程。这里的数据集包含 200 条典型的 `prefix → continuation` 样本，每条样本由一个问题或上下文片段（prefix）和对应的续写文本（continuation）组成。为了避免直接暴露数据文件，本处仅展示数据结构示例：

```json
{"prefix": "选择燃气热水器时，一定要关注这几个问题：1、出水稳定性要好，...", "continuation": "另外，...，长期使用磁化水沐浴更利于身体健康。"}
{"prefix": "迈克尔.乔丹在NBA打了15个赛季。...1984年的NBA选秀大会，乔丹在首轮第3顺位被芝加哥公牛队选中。", "continuation": "1986-87赛季，乔丹场均得到37.1分，...2009年9月11日，乔丹正式入选NBA名人堂。"}
```

> 注意：在实际评测中，模型会基于 prefix 自动预测 continuation，并与 reference continuation 进行对比。

接下来使用 `run_dureader.py --mode eval` 对模型进行评测。评测过程中，计算了三类核心指标：PPL（困惑度）、Loss（平均交叉熵）和 BLEU（2-gram F1 近似）。

下面展示基座模型与预训练模型在评测集上的指标对比结果：

| 模型    | PPL     | Loss   | BLEU   |
| ----- | ------- | ------ | ------ |
| 基座模型  | 27.5429 | 3.3157 | 0.1194 |
| 预训练模型 | 1.9688  | 0.6774 | 0.1786 |

可以看到：

* **PPL 改善明显**：由 27.5429 降至 1.9688，约下降 92.85%，显示模型在给定 prefix 下对 continuation 的不确定性显著降低，预测更稳定。
* **Loss 同步下降**：由 3.3157 降至 0.6774，约下降 79.57%，说明 token 级条件概率分布与真实分布更接近，模型生成更准确。
* **BLEU 稳定提升**：由 0.1194 升至 0.1786，约提升 49.58%，反映生成文本在局部 n-gram 匹配上更加符合参考文本，生成质量得到增强。

总体来看，预训练模型在三项指标上均优于基座模型，验证了领域继续预训练（Domain-specific PT）能够有效提升模型在特定场景下的续写能力。在实际应用中，PPL 与 Loss 对语言建模能力更敏感，而 BLEU 还受表达多样性影响，因此仅做 PT 时，BLEU 提升幅度相对有限。
