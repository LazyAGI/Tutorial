# 第3课时：分布式训练技术概览

## 1. 进阶专题与实用技巧

在大模型训练里，“跑得动”只是第一步，“跑得稳”才是关键。很多时候，模型并不是学不会，而是训练过程本身不稳定：loss 飙升、梯度爆炸、显存突然爆掉……这些都可能让训练直接“崩盘”。这一节，我们只讲最重要、最容易理解的稳定化技巧。

### 1.1 稳定训练与高效优化

模型为什么会突然学不动、学偏了，甚至直接崩掉？只有搞明白“崩溃的原因”，我们才能谈“如何让它稳”。

#### 为什么训练会“发散”或“崩溃”？

造成训练不稳定的原因其实非常常见，例如：

- 学习率太大：最典型的“炸模型”元凶，模型每一步都跳得太远，越跳越偏。
- 梯度爆炸：梯度突然变得非常大，权重一下子被推飞，loss 直接升天。
- Batch 太小 / 数据分布波动大：梯度估计不稳定，模型学一天忘一天。
- 混合精度误差积累：FP16 训练里常见，某些数值被“舍入”到不合理范围。

简单来说：  
> 模型不是不听话，是你的训练参数让它“心态崩了”。

#### 常见的训练稳定化方法

**（1）学习率调度（LR Scheduler）**

几乎所有训练框架都会默认提供，例如：

- Warmup：训练前几百或几千步先把学习率从 0 慢慢升上去 → 避免模型一上来就剧烈震荡  
- Cosine / Linear Decay：后期降低学习率 → 让模型慢慢“收敛”，别学得太猛  

前期别冲太快，后期别闹太凶。

**（2）梯度裁剪（Gradient Clipping）**

当梯度突然变得非常大时，把它强行“剪短”，避免把模型权重推爆。

常见形式：

```text
clip_grad_norm = 1.0
```

就像给训练过程系了一个安全带。

**（3）损失函数平滑 / Label Smoothing**

让模型不要对标签“过度自信”，提升稳定性。尤其在分类和语言模型训练里很常见。

#### 混合精度训练与显存优化

想让训练速度更快、显存更省，最简单有效的方法就是混合精度：

* FP32（最安全） → 显存大，速度慢
* FP16 / BF16（现在主流） → 显存小、速度快
* FP8（未来趋势） → 极低显存成本（但需要硬件支持）

混合精度训练通常还能自动处理一些数值溢出问题（AMP），既快又稳，是现代训练的基本配置。

与此同时，还可以结合：

* Gradient Checkpointing：用计算换显存，节省 30%～50% 显存
* Zero / Offloading 技术（如 DeepSpeed / Colossal-AI）：把一些参数放到 CPU、NVMe
* 小 Batch + 累积梯度（Gradient Accumulation）：小显存也能训练大模型

混合精度负责省，梯度技术负责稳。

### 1.2 模型训练过程的管理与恢复

模型训练不是“一键启动 → 等着收菜”这么简单，它更像是长跑：节奏要稳、状态要看、摔倒了还能接着跑。本节带你掌握三件事：怎么看训练效果、怎么从中断恢复、怎么用日志排查问题。

#### 训练可视化：看曲线判断模型是不是“学明白了”

训练曲线就像模型学习成绩单。最常看的指标包括：

* Loss 曲线：整体向下说明模型在学习；忽上忽下可能是在纠结；下降太快可能在“死记硬背”（过拟合）。
* 验证集指标（如 accuracy / F1 / perplexity）：训练集表现好但验证集变差，就是典型过拟合信号。
* 学习率变化：如果用 Scheduler，看看学习率是否按预期下降。

训练过程必须“可视化”，而不是“盲盒式训练”。常用工具包括 TensorBoard、Weights & Biases、MLflow 等，开箱即用，看曲线比看天象还清晰。

#### Checkpoint：中断后继续跑，不用从头再来

训练大模型最怕的不是显存不足，而是“训练到一半服务器重启了”。为此，Checkpoint（模型快照）就显得尤其重要。保存内容通常包括：

* 模型参数
* Optimizer 状态
* 学习率调度器状态
* 当前训练到第几步 / 第几轮

有了这些，即使训练中断，也可以做到：

* 继续训练（resume training）：从最新 checkpoint 接着跑，不浪费显卡时间。
* 回滚训练：如果发现某次实验效果退步，可以回到更稳定的 checkpoint 重跑。

一句话：Checkpoint 是训练的“存档系统”，千万别关掉自动保存。

#### 训练日志与监控：帮你快速定位“模型为什么闹脾气”

当训练出现问题，比如 loss 不下降、梯度爆炸、显存暴涨，日志是你最重要的侦探工具。

你应该确保：

* 每轮输出当前 loss、学习率、显存占用
* 异常时记录错误堆栈
* 保存最近几次评估指标对比

配合监控系统（如 Prometheus + Grafana）可查看 GPU 温度、利用率、网络 IO 等硬件指标。

日志告诉你“问题出在哪”，监控告诉你“哪里卡住了”。两者配合，就能快速判断是数据异常、模型结构不稳、还是系统资源不足。

### 1.3 小规模复现实验思路

在接触大模型训练之前，强烈建议先做“小规模复现实验”。既不烧显卡，也不费钱包，还能把整个训练流程从头到尾走一遍，效果堪比“沙盘推演”。

目标很简单：
> 用更小的模型 + 更小的数据集，验证整个训练链条是不是顺畅的。

#### 使用轻量模型：从“小鸟”先飞飞

你没必要一上来就训上百亿参数的大模型，那就像让新手司机直接上 F1 赛道。

更实用的做法是：

* GPT-2 small（124M）

    * 经典结构简单清晰
    * 单卡 8G 就能跑
    * 常用于教学与原型验证

* TinyLlama（1.1B / 3B 限定版）

    * 结构与主流 Llama 系列一致
    * 参数量小但拥有完整组件
    * 非常适合学习整个 Llama 训练流程

这些“小模型”虽然能力一般，但非常适合验证训练逻辑，例如：

* 数据是否能正常加载？
* Tokenizer 是否一致？
* Loss 是否如预期收敛？
* Checkpoint 是否能断点恢复？
* 训练脚本的配置是否正确？

#### 使用小数据集：验证原理比“喂饱模型”更重要

小规模实验不需要动用几十 GB 的语料，几万条数据就能达到效果。

可选的小数据集包括：

* WikiText-2（语言建模经典入门）
* Penn Treebank（PTB）
* OpenWebText 的一个小切片
* 自己准备的小规模文本（如 5MB～20MB）

这些数据的特点：

* 干净、结构简单
* 容易跑通一个 epoch
* 观察 loss 曲线非常直观

你需要的不是训练一个“强大模型”，而是验证：

* 预处理流程正确吗？
* 数据管道会不会卡顿？
* 训练能否正常启动？
* 模型的损失是否合理下降？
* 评估模块是否按预期工作？

只要这些环节都没问题，你就可以安心地把实验规模放大。

#### 小规模复现的三大收益

小模型 + 小数据的组合，能帮你在最短时间内得到最大的反馈：

* 降低试错成本
    10 分钟就能跑完一个 epoch，比看一集剧还快。
* 快速验证流程
    架构改动、loss 函数变动、预处理调整，都能即时看到效果。
* 大规模训练前的彩排
    保证所有组件（数据 → 模型 → 优化器 → 日志 → checkpoint）运行无误。

真正的大模型训练往往成本巨大，高效的团队都会先从小规模 sanity check 开始，这不仅是好习惯，更是防止资源浪费的工程实践。
